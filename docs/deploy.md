# Deploying on k3s

Namespace `orb`. Everything single-replica. Phase 0 facts (2026-11-02): k3s v1.34 with one Ready node (`kubernetes-lab-1`, 192.168.40.129, amd64), default Traefik, k3s ServiceLB (no MetalLB), no cert-manager, `local-path` default StorageClass, Technitium for LAN DNS, images on GHCR under `ltruong0`.

## Mosquitto

| Object | Spec |
|---|---|
| Deployment | `eclipse-mosquitto:2.0.22`, 1 replica, `strategy: Recreate`, non-root (uid 1883). An init container copies the ConfigMap and Secret into a memory `emptyDir` owned by 1883 with mode 0600: Mosquitto 2.x warns about root-owned or world-readable acl/password files and says future versions will refuse them. |
| ConfigMap `mosquitto-config` | `mosquitto.conf` and `aclfile` from `deploy/k8s/base/mosquitto/` (kustomize `configMapGenerator`; the files live under the base because kustomize refuses sources outside it) |
| Secret `mosquitto-passwd` | `passwd` generated by `make mosquitto-passwd` (pure-Python `tools/mosquitto_passwd.py`, same PBKDF2-SHA512 format as `mosquitto_passwd`) from `.env` into the gitignored `deploy/k8s/overlays/homelab/secrets/`, applied via `secretGenerator` |
| PVC `mosquitto-data` | 1 Gi, `local-path` (set in the homelab overlay). Single node, so no pinning needed; `local-path` ties the data to `kubernetes-lab-1`. |
| Service `mosquitto` | `ClusterIP` in the base (`mosquitto.orb.svc:1883` for the hub), patched to `type: LoadBalancer` in the homelab overlay. k3s ServiceLB exposes it on the node IP 192.168.40.129. DNS: A record `mqtt.marcellolab.com → 192.168.40.129` in Technitium. |
| Probes | TCP 1883 |

ACL behaviour worth knowing: Mosquitto 2.x **grants** a SUBSCRIBE to a topic the client may not read (even `orb/#`) and enforces `read` at delivery time. So "cannot read" means "never receives", not "SUBACK fails". `tests/test_broker_acl.py` checks exactly that, plus LWT and retained-state survival across a restart. `make broker-test` runs it against Mosquitto in Docker, `make broker-check` against the cluster.

## msg-hub

| Object | Spec |
|---|---|
| Deployment | `deploy/k8s/base/hub.yaml`: 1 replica, `strategy: Recreate` (SQLite is single-writer), runs as uid 1000, `envFrom` ConfigMap `hub-config` + Secret `hub-secret` |
| Image | `hub/Dockerfile` (build from the repo root: `make image`): `python:3.12-slim` + `fonts-noto-color-emoji`, deps from `uv.lock`, runs as uid 1000, `CMD msg-hub` on 8080. Pushed to `ghcr.io/ltruong0/orb-messenger/msg-hub`, pulled with a per-namespace `ghcr-secret` (`kubectl -n orb create secret docker-registry ghcr-secret ...`), same pattern as the other lab apps |
| PVC `hub-data` | 5 Gi at `/data` (DB + media), `local-path` in the homelab overlay |
| Secret `hub-secret` | `HUB_PIN`, `SESSION_SECRET`, `MQTT_PASSWORD`, generated by `make hub-secrets` from `.env` into the gitignored `secrets/hub.env` (`secretGenerator`); no name-suffix hash, so after changing it run `kubectl -n orb rollout restart deploy/hub` |
| ConfigMap `hub-config` | `MQTT_HOST=mosquitto.orb.svc`, `MQTT_USER`, `MEDIA_BASE_URL=http://orb.marcellolab.com`, `HUB_TZ` (overlay `configMapGenerator` literals). `users.yaml` ships inside the image; to change names, edit `hub/users.yaml` and rebuild, or mount a ConfigMap at `USERS_FILE`. |
| Secret `ghcr-secret` | Pull secret, created by hand once: `kubectl -n orb create secret docker-registry ghcr-secret --docker-server=ghcr.io --docker-username=ltruong0 --docker-password=<PAT with read:packages>` (or copy the one from another lab namespace). Not managed by kustomize. |
| Service `hub` | ClusterIP 8080 |
| Probes | `/healthz` liveness, `/readyz` readiness |
| Resources | requests 100m / 128Mi, limits 500m / 512Mi (Pillow spikes on big photos) |

Release: bump `version` in `hub/pyproject.toml` (the Makefile uses it as the image tag), `make image-push` (needs `docker login ghcr.io` with a token that has `write:packages`; the build targets `linux/amd64` with buildx, see decisions 38), `make set-image`, commit, `make deploy`, `make deploy-status`.

First deploy on 2026-11-03: `kubectl apply -k` created everything in one go; the GHCR package is private, so the `ghcr-secret` pull secret (token with `read:packages`) had to exist first.

## Ingress

- `https://orb.marcellolab.com/` → `hub:8080` for phones. TLS comes for free from Traefik's default `TLSStore` (`kube-system/marcellolab-tls`, an mkcert wildcard for `*.marcellolab.com`, valid to 2028-01). Phones must trust the mkcert root CA for the PWA to be installable (service worker + "Add to Home Screen"); without it the page still works over HTTPS with a warning or over plain HTTP. Ingress annotations as the other lab apps: `router.entrypoints: websecure`, `router.tls: "true"`. DNS: A record `orb.marcellolab.com → 192.168.40.129`.
- `http://orb.marcellolab.com/media/*` → `hub:8080` **without** the HTTPS redirect, so orbs can fetch over plain HTTP. A second Ingress (`hub-media`) on the `web` entrypoint matching `/media`. No global redirect middleware exists in the lab today. Both live in `deploy/k8s/overlays/homelab/hub-ingress.yaml`.
- `/api/events` (SSE): disable response buffering. Traefik passes SSE through, but check that no middleware compresses it.

## Layout

```
deploy/k8s/
  base/            namespace, mosquitto, hub, services, pvcs, kustomization.yaml
  overlays/homelab/ ingress, LB IP, storageClass, image tag, secretGenerator (from gitignored files)
```

## Backups

Snapshot the two PVCs. `hub.db` can be copied hot with `sqlite3 hub.db ".backup /data/backup.db"`. Optional CronJob.
